★Collapse the Order intake pipeline

Start here. An order passes through four modules that each do almost nothing — OrderHandler → OrderValidator → OrderNormalizer → OrderRepo. Every interface is nearly as wide as its implementation. One deep OrderIntake module absorbs all four. The seam moves to one place, and that place is the test surface.

1Deepen Order intake into one module

Strong in-process order/handler.py · order/validator.py · order/normalizer.py · order/repo.py

Four modules split one job. Each interface is nearly as complex as its implementation, so each is shallow. Understanding one order means reading all four. The deletion test says yes: fold them together and complexity concentrates in one place instead of spreading.

2Stop pricing leaking across the repo seam

Worth exploring ports & adapters order/repo.py:64 · pricing/client.py

OrderRepo should own persistence. It reaches into PricingClient mid-write to re-price the order. Pricing leaks across the seam: a persistence change now needs a pricing double to test, and a pricing change can break a save.

flowchart LR A[OrderIntake] --> B[OrderRepo] B -.leaks pricing.-> C[PricingClient] B --> D[(orders db)] classDef leak fill:#c5221f,stroke:#c5221f,color:#ffffff; class B,C leak

OrderRepo calls pricing while it writes. Put a Pricing port in front, so persistence and pricing sit on two sides of one seam.

Before — repo re-prices mid-write
order/repo.py 
def save(self, order):
    total = PricingClient().price(order)   # leak
    order.total = total
    self.db.insert(order)
After — pricing behind a port
order/repo.py 
def __init__(self, db, pricing: Pricing):
    self.db, self.pricing = db, pricing

def save(self, order):
    order.total = self.pricing.price(order)
    self.db.insert(order)
  • The Pricing port is the seam persistence tests mock.
  • Two adapters justify it: the HTTP client in prod, an in-memory price in tests.
  • A pricing change can no longer break a save.
Contradicts ADR-0007 ("repositories may read pricing inline to avoid an extra hop"). Worth reopening: that hop is now the only thing forcing a live pricing service into every persistence test.

3Shrink the Notifier interface

Speculative local-substitutable notify/notifier.py

Notifier exposes seven methods — email, sms, push, and four format helpers. The interface is nearly as wide as the implementation, so it is shallow. One notify(event) method could hide the channel choice inside. Speculative: the seven methods have few callers, so the payoff is smaller than it looks.

After — deep

✓Deliberately leaving alone

  • The Money value object. Small interface, real implementation — already deep. No change.
  • The two-line ClockAdapter seam. One adapter today, but the test suite is the second: a fake clock drives the expiry tests. Two adapters, real seam. Kept.
  • The InventoryGateway port. ADR-0003 records why inventory sits behind a seam. Not re-litigated.

Deepen Order intake first. It collapses four shallow modules into one deep module, and the seam it leaves is the surface every intake test drives.
