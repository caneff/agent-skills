# Multi-worker trial: controller briefs

Hand-written run briefs for the trial on the herdr lane ([agent-skills #781](https://github.com/caneff/agent-skills/issues/781)), written from the map's decisions ([#776](https://github.com/caneff/agent-skills/issues/776)) because `burndown` and `implement-spec` were parked at the time. Both were unparked in #899; these briefs are the record of that trial, not current procedure. Each brief is pasted whole into a fresh Claude session opened on the target repo's primary checkout, on its default branch. Chris watches in herdr and merges.

Order: the spec run first (done 2026-09-14); the burn once `implement-dispatch --spec` ([#787](https://github.com/caneff/agent-skills/issues/787), landed) and the spec run's lane fixes (#819–#824) have landed.

## Brief 1: spec run

```
You are the Controller of a spec run: /implement-spec by hand, before the skill is written. Terms (Run, Slot, Clump, Worker, Controller, Wake, Workspace) are in ~/.agents/skills/CONTEXT.md; read it first. Read ~/.agents/skills/implement/SKILL.md § Dispatch, § Control and § The PR so you know what a worker does and sends. Record what hurts as you go: every rough edge is a comment on https://github.com/caneff/agent-skills/issues/781, one per comment, as it happens, not at the end.

Target: spec #366 (Up to N) in caneff/sudokumaker-custom-constraints. Primary checkout: /home/caneff/src/sudokumaker-custom-constraints (you are in it, on the default branch). Slots: 5.

1. Exploration pass, once, before any dispatch. Run one in-process Explore subagent (Agent tool, subagent_type Explore, model sonnet). Its brief: read the spec and every open child ticket end to end plus every "Settled:" comment on them; for each ticket list the files it would touch (by name), its size tag (docs-only, one-file, multi-file) and its collisions (a file two tickets both touch); check every settled decision that asserts runtime behaviour against the code and quote the implementing line anchored on a name, never a bare line number; write the whole thing to ~/.cache/burndown/sudokumaker-custom-constraints.notes.md with one section per ticket whose heading starts exactly `## #<n>` and one section headed exactly `## Collisions`; return a summary under 40 lines. A decision the code contradicts is a ruling for Chris: post it on the ticket before dispatching that ticket, and wait for his answer.

2. Clump. Draw the collision graph over the open children and take its connected components. Each component is one Clump: one worker, one workspace, one PR closing every ticket in it. Write the clumps under `## Collisions` in the notes file, each with its tickets in number order and the union of their files.

3. Closing ticket. Create one more child of the spec now, titled "Spec close: end-to-end test and spec-level review", labelled ready-for-agent, blocked by every other open child (native blocked-by edges; the tracker doc at ~/.agents/skills/docs/agents/issue-tracker.md has the gh api call). Its body: write one end-to-end test over the whole spec's acceptance criteria if none exists, run the repo's full test seam, review the whole landed range since the spec's first slice with /multi-axis-code-review, fix or file every finding, and close the spec issue in the PR body. It is a ticket like any other; the loop reaches it last.

4. The loop. The frontier is: open children of the spec, labelled ready-for-agent, with no open blocker and no assignee, grouped by clump, lowest ticket number first. While there is a frontier clump and a free slot:
   - Run `uptime` and `free -g`. If the 1-minute load is above 24 or free memory is under 6 GB, dispatch nothing and record it as a hurt.
   - `implement-dispatch --repo /home/caneff/src/sudokumaker-custom-constraints <lowest ticket in the clump>` (add `--model opus` when the notes tag it multi-file). Relay its report line. If the clump has more than one ticket, immediately SendMessage the new worker (its agent name is in the dispatch report) with: the other ticket numbers in number order, one commit per ticket carrying that ticket's `Closes #<n>`, the clump's own files, and the notes file path with the `## #<n>` headings to read. Record whether that message was enough as a hurt or a non-hurt.
   - Append `burning #<n>` for each ticket in the clump to ~/.cache/burndown/sudokumaker-custom-constraints.progress.
   Then end your turn. Your wait is going idle. Never sit in a long tool call, a sleep, a blocking wait or `herdr agent wait` while workers are out: their messages are held until the call returns.

5. On every wake (a worker's message is your next turn):
   - A question: rule on it yourself under the Controller entry in CONTEXT.md; escalate to Chris in your terminal only a spec-ruling change, a new dependency, an irreversible deletion. Answer the worker by SendMessage to its name.
   - "PR up": print the worker's two `! ` lines to Chris exactly as sent, append `#<n> pr <url>` for each of its tickets to the progress file, then run `python3 ~/.agents/skills/burndown/cost.py <workspace path>` and append `<n> <builder> <review> - 0` to ~/.cache/burndown/sudokumaker-custom-constraints.cost (first ticket of the clump gets the numbers, the rest get 0).
   - After Chris says merged (or `gh pr view <pr> --json state` shows MERGED on a later wake): append `#<n> landed <sha>`, then re-run step 4.
   - Before ending any turn with workers out, check each live worker with `herdr agent get <agent>`. One that is gone with no report is parked: comment on its ticket what was found, swap in-progress to ready-for-human, append `#<n> parked: <why>`, and tell Chris in your terminal. Two consecutive parks with no landing in between stop the run: append `done`, report, end.

6. When the closing ticket's PR is merged: append `done`, post a final comment on https://github.com/caneff/agent-skills/issues/781 with the tally (tickets landed, parked, dispatches, wakes, box checks that refused, and the hurt list in one place), and stop.

Rules that stand throughout: you never merge; you never edit code in /home/caneff/src/sudokumaker-custom-constraints; every question a worker asks that times out is the worker's to answer safely, not yours to chase; a worker's report that arrives cut off is read from the file it names.
```

## Brief 2: burn

Written after brief 1 ran (tally and hurt list: the last comments on #781). Brief 1 above is kept as it ran; brief 2 folds in its fixes. Run it once the lane fixes from that run have landed: #819 (dispatch reports both names), #820 (Stop hook alerts the controller), #821 and #823 (merge-cleanup claim and counts), #822 (worker clears `.scratch/`), #824 (closing-keyword check). Where a line below exists because of a spec-run hurt, the hurt number follows in brackets.

```
You are the Controller of a burn: /burndown by hand, before the skill is written. Terms (Run, Slot, Clump, Worker, Controller, Wake, Workspace) are in ~/.agents/skills/CONTEXT.md; read it first. Read ~/.agents/skills/implement/SKILL.md § Dispatch, § Control, § The PR and § The merge so you know what a worker does and sends and what you do at merge. Merging follows the hard rules in ~/.claude/CLAUDE.md and § The merge as they read when you act, not any restatement here; re-read them before every merge. Record what hurts as you go: every rough edge is a comment on https://github.com/caneff/agent-skills/issues/781 starting "Burn run, hurt:" (or "non-hurt:"), one per comment, as it happens.

Target: the open ready-for-agent queue of caneff/sudokumaker-custom-constraints, lowest numbers first, capped at 15 tickets. Primary checkout: /home/caneff/src/sudokumaker-custom-constraints. Slots: 5. Run id: burn-<YYYY-MM-DD-HHMM> at start.

0. Where you are. Run `git -C /home/caneff/src/sudokumaker-custom-constraints rev-parse --show-toplevel` and `git branch --show-current` in your own cwd. Your cwd must be that primary checkout on its default branch, not a worktree under .claude/worktrees. If not, stop and tell Chris before anything else. [1]
   Append `run <run-id> start` to ~/.cache/burndown/sudokumaker-custom-constraints.progress and ...cost. Every later reader of those files reads from the last `run` line down. [5]

1. Exploration pass, once, before any dispatch. Run one in-process Explore subagent (Agent tool, subagent_type Explore, model sonnet). Its brief: read every ticket in the capped queue end to end plus every "Settled:" comment on them; for each ticket list the files it would touch (by name), its size tag (docs-only, one-file, multi-file), its collisions (a file two tickets both touch) and the repo's end-to-end test seam that covers it and what that seam cannot see (from AGENTS.md or the test tree) [19]; check every settled decision that asserts runtime behaviour against the code, quoting the implementing line anchored on a name, and sort each mismatch into exactly one of: NOT-YET-BUILT (the code lacks it and a ticket in this queue builds it; name that ticket) or CONTRADICTED (the code does something different from what the decision claims exists) [4]; list the questions a builder would otherwise stop to ask (acceptance the ticket leaves ambiguous, behaviour a player or user needs that it is silent on, a design choice it leaves open), each with a recommended answer and that answer's cost; write it all to ~/.cache/burndown/sudokumaker-custom-constraints.<run-id>.notes.md with one section per ticket headed exactly `## #<n>` and one headed exactly `## Collisions`; return a summary under 40 lines.
   - CONTRADICTED is a ruling for Chris: post it on the ticket, hold that ticket, wait for his answer. NOT-YET-BUILT is a note only.
   - A docs-only ticket without the `documentation` label: add the label before dispatch, and comment why, so dispatch picks the light tier. [2]

1b. Ruling round, before any dispatch. Put every CONTRADICTED item and every listed builder question to Chris in your terminal: a few numbered questions per round, each with your pick and its cost, until none is open. Post each answer on its ticket as a `Settled:` comment, so the worker reads it in step 3's notes. Dispatch in step 3 only tickets with no open question; a ticket still waiting on an answer is held, not the whole burn. Count the rounds and questions for the tally. [spec run: 3 Chris rulings mid-run, 1 controller ruling reversed]

2. Clump. Draw the collision graph over the queue and take its connected components. Each component is one Clump: one worker, one workspace, one PR closing every ticket in it. Write the clumps under `## Collisions`, each with its tickets in number order and the union of their files. Merge method is squash: per-ticket commit shas do not survive it, so nothing (a test fixture, a pinned REF_COMMIT, a floor) may pin a sha from the branch; pin a committed copy instead. [10]

3. The loop. A clump is on the frontier when every ticket in it is open, ready-for-agent and unassigned, and no ticket in it has an open blocker outside the clump; blockers between tickets of the same clump are ignored. [3] Frontier clumps go lowest ticket number first. While there is a frontier clump and a free slot:
   - Run `uptime` and `free -g`. If the 1-minute load is above 24 or free memory is under 6 GB, dispatch nothing and record it as a hurt.
   - `implement-dispatch --repo /home/caneff/src/sudokumaker-custom-constraints <lowest ticket in the clump>` (add `--model opus` when the notes tag it multi-file). Relay its report line. Record the worker's herdr agent name (stable across restarts) and its Claude session name (from the dispatch report, else ListAgents). [6]
   - If the clump has more than one ticket, claim the rest yourself now: for each other ticket, `gh issue edit <n> --repo caneff/sudokumaker-custom-constraints --add-assignee @me --remove-label ready-for-agent --add-label in-progress`. [9] Then SendMessage the worker's session name with, in one message: the other ticket numbers in number order and that they are already claimed; that blockers between them are internal to the clump and to be ignored; that each ticket's last commit carries its `Closes #<n>` (never squash, reorder or rewrite commits to get there) [13]; that the PR body lists every ticket as a bare `Closes #<n>` line, not in backticks [20]; the clump's own files; the notes file path and the `## #<n>` headings to read; and that every question and the PR-up report go to you by SendMessage, never printed in its pane [7, 9]. Record whether that message was enough.
   - Append `burning #<n>` for each ticket in the clump to the progress file.
   Then end your turn. Your wait is going idle. Never sit in a long tool call, a sleep, a blocking wait or `herdr agent wait` while workers are out: their messages are held until the call returns.

4. On every wake:
   - A question: rule on it yourself under the Controller entry in CONTEXT.md; escalate to Chris in your terminal only a spec-ruling change, a new dependency, an irreversible deletion, or something a player or user needs that the ticket is silent on. A ruling on runtime behaviour is checked against what ships (the live editor, not the headless bundle or another proxy) before you give it [11]. Before escalating, you may commission the worker to run one bounded probe (a stated cap on runs, time and tools) so Chris gets a table, not options in the abstract.
   - "PR up": run `gh pr view <pr> --repo caneff/sudokumaker-custom-constraints --json isDraft,mergeStateStatus,closingIssuesReferences` and check not-draft, CLEAN, and every clump ticket in closingIssuesReferences; if not, send it back [20]. Then merge per § The merge and the hard rules, in this pane, never relayed to another session [merge wake]. Append `#<n> pr <url>` then `#<n> landed <sha>` for each ticket, run `python3 ~/.agents/skills/burndown/cost.py <workspace path>` and append `<n> <builder> <review> - 0` to the cost file (first ticket of the clump gets the numbers, the rest 0), then re-run step 3.
   - A "stopped without reporting" alert, or a worker you find done with no report: `herdr agent read <agent>` for what it printed, then treat it as the report it should have sent. [7, 14]
   - Before ending any turn with workers out, check each live worker with `herdr agent get <agent>`. One that is gone with no report is parked: comment on its ticket what was found, swap in-progress to ready-for-human, append `#<n> parked: <why>`, tell Chris. Two consecutive parks with no landing between stop the run: append `done`, report, end.

5. After a restart (WSL or harness): session names change. Run ListAgents, match each live worker to its herdr agent name, and SendMessage every live worker your new session name as its controller. Record the rename as a hurt only if a message was lost. [12]

6. A ready ticket whose parent carries the `spec` label is not dispatched plain: dispatch `implement-dispatch --spec <parent> --slots <k>` with k taken from the burn's free slots; it counts against the cap as its number of open slices and reports back as one unit. Its closing ticket gets the list of the spec's merge shas from the progress file, not a git range. [16]

7. When the queue is empty or the cap is reached and every PR has landed: append `done`, post a final comment on https://github.com/caneff/agent-skills/issues/781 with the tally (tickets landed, parked, dispatches, wakes, reports that never arrived, box checks that refused, Chris rulings before dispatch and after it, controller rulings reversed, and the hurt list in one place), and stop.

Rules that stand throughout: you never edit code in /home/caneff/src/sudokumaker-custom-constraints; merging and cleanup follow ~/.claude/CLAUDE.md and implement/SKILL.md § The merge as they read at the moment you act [15]; every question a worker asks that times out is the worker's to answer safely, not yours to chase; a worker's report that arrives cut off is read from the file it names.
```
